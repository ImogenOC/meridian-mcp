# Security model

The trust boundary is the launch configuration, not a tool call. `MERIDIAN_MCP_MODE`, `MERIDIAN_MCP_ROOTS`, `MERIDIAN_MCP_REPOSITORIES`, `MERIDIAN_MCP_COMPILERS`, `MERIDIAN_MCP_STATE_DIR`, and `MERIDIAN_MCP_RIFT_BUILD` are loaded before stdio starts and cannot be expanded by the client. The full-build values are exactly `disabled`, `offline`, and `network`; callers can select only `network_mode=offline` or `network_mode=allow` within that ceiling.

`MERIDIAN_MCP_REPOSITORIES` authorizes local Git repository membership, not arbitrary siblings and not remote identities. Startup uses fixed non-shell Git commands to enumerate linked worktrees, canonicalizes every candidate, and verifies that each candidate resolves to the configured repository's same Git common directory. The common-directory path is hashed only to produce a bounded local identity; it is not portable provenance and is never substituted for a source revision. Exact canonical duplicates are removed, and an explicit root outranks discovery. Changing repository or root authorization requires a server restart.

Existing inputs are canonicalized and must remain below an allowed root. New outputs require an existing contained parent. Existing outputs require `overwrite=true`. Caller-selected compilers must match the canonical allowlist. Automatically discovered DreamMaker installations remain a server policy decision.

Development mode requires a pre-existing non-symlink private state directory outside and not above any workspace root. A persistent regular lock file provides operation-scoped exclusive operating-system locks, serializing bounded reads, enumerations, and writes across concurrent MCP processes without making file existence a lifetime ownership claim. Related provenance records are read under one lock. Active runtime-integrity journals hold separate per-session liveness locks, and recovery changes a journal only after a non-blocking acquisition proves that its owner no longer holds the lock. Abrupt process exit releases both kinds of operating-system lock. Record paths reject traversal and symlink escapes; documents and enumerations are bounded, writes use same-directory temporary files and atomic replacement, and installed JSON is reopened and parsed before success. These records are local policy evidence, not portable source provenance, and must not be included in published evidence bundles.

Fixture manifests are data-only: bounded forward-slash relative paths, fixed input roles, exact proc signatures, and literal tokens. They reject unknown fields, commands, URLs, globs, environment expansion, traversal, aliases, symlinks, and missing declared inputs. Launch provenance is revalidated from disk immediately before spawn. A known stale managed DMB is never launched; an unmanaged DMB is reported as unverified and may be rejected by `require_verified_provenance`.

Network operations target the loopback DreamDaemon owned by the server. The product has no internet-facing administration and no supported BYOND client-login protocol. Runtime lifecycle methods manage only the stored child handle.

Ordinary DreamDaemon launches persist a protected-root snapshot before spawn. Git roots retain index object identity plus worktree SHA-256 and size; other roots use fixed entry/byte limits. Only exact MCP-owned file paths can be excluded. The monitor and lifecycle checks record evidence but never restore, checkout, delete, rewrite, or stage workspace content. Process termination is attempted before a deletion violation is returned. Unfinished private journals are marked as recovery observations on startup only when their protected root remains authorized.

Native evidence tools accept only contained files with an explicit fixed kind. They do not autodetect formats or accept URLs, globs, scripts, expressions, JSONPath, parser plugins, or caller transformations. File, total-byte, row, column, line, depth, string, group, phase, and output limits are fixed. Protected identifier fields are always removed before grouping or returned samples, and protected `name=value` text segments are sanitized. Raw files are neither modified nor copied into results.

Tracy is disabled by default and cannot be enabled by a tool call. Startup validation requires exact source and owned-patch revisions, protocol 82, platform/architecture identities, BYOND bounds, contained helper paths, and SHA-256 hashes. The runtime binds byond-tracy to `127.0.0.1`, uses fixed `-params tracy`, and excludes caller-defined environment values. The helper accepts bounded schema-2 fixed commands over private stdio and has no arbitrary code, expression, Python, HTTP, or discovery surface. Request IDs are multiplexed; unknown or duplicate responses fail the transport. Trace outputs never overwrite, paired sidecars bind the exact trace hash and immutable experiment identity, and offline comparisons fail before parsing when technical/workload identity is incompatible. Network observations are limited to owned process identities and the configured loopback profiler port; `network_isolation_confirmed` and `capture_complete` remain false. CI evidence uploads explicitly exclude raw `.tracy` files.

On Windows, `dm_compile` and `rift_compile` use a shared bounded process runner. An owned Job Object terminates descendants on timeout or cancellation. Standard output and error are size-limited, and generated artifacts are measured with timestamps, sizes, and SHA-256 hashes. `rift_compile` constructs the command from a qualified parsed profile, a trusted system `cmd.exe`, and the canonical root `RIFT_BUILD.cmd`; its schema exposes no arbitrary executable, path, argument vector, target, URL, credential, or environment field.

The full-build child receives a sanitized allowlist of required operating-system variables plus the selected DreamMaker path and fixed build flags. A caller cannot inject credentials. `TG_BOOTSTRAP_CACHE` is retained only when its canonical directory is inside an allowed root. Offline mode checks a warm pinned cache and supplies Bun and pip no-network controls before delegating; these controls are cooperative and are not proof that the operating system blocked all network activity.

When `capture_network=true`, Windows periodically samples TCP and UDP owner tables for the owned process tree. Short-lived endpoints can be missed, so samples are observational, bounded, and always include `capture_complete: false`. Audit unavailability is a warning rather than false proof of no traffic.

Tool errors are caller-visible MCP tool results with stable policy codes such as `path_outside_workspace`, `output_exists`, `executable_not_allowed`, and `tool_not_available`. Path-policy failures also report policy source `server_startup_configuration`, containment mode `immutable_startup_roots`, effective roots with their authorization sources, and bounded recovery guidance. `dm_server_status` exposes the same effective policy and readiness summaries to the local MCP caller without listing private state-record contents. Protocol errors are reserved for requests the SDK cannot route.

These controls reduce accidental and model-driven misuse; they do not make an untrusted repository safe to compile or run. Development mode should be used only with trusted workspaces.
