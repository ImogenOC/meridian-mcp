# DMI resource limits

DMI analysis loads validate the transitive path policy, read at most the configured file ceiling plus one detection byte, and hash the bounded input before consulting the decoded cache. Unchanged content reuses the existing asset and generation. A shared admission semaphore permits four blocking asset workers by default; each worker retains its permit until it finishes, including after caller cancellation. File checks, reads, and hashing can overlap. Pixel decoding is serialized by the cache lock, which also coalesces concurrent requests for the same identity.

The root decoder checks image dimensions, decompressed Description metadata, state/frame counts, and arithmetic before allocating full pixels. It validates the concatenated IDAT stream with bounded inflation before entering the pinned PNG pixel decoder, whose internal inflation ceiling alone is not a hard allocation bound. This temporary is released before pixel allocation. Cold loads therefore inflate the image twice; cache hits do neither. Animated PNG chunks are rejected rather than decoding an unchecked additional image. Owned parity fixtures cover ordinary DMI metadata, zero frames/delays, Adam7 interlacing, palettes/transparency, grayscale, RGB, and 16-bit RGBA conversion.

Duplicate scans and icon audits retain one decoded asset per canonical identity in an invocation, sharing it across references and audit phases. Before loading the next asset, they enforce default aggregate budgets of 512 MiB final RGBA pixels, 32 MiB uncompressed metadata, 100,000 states, and 1,000,000 directional frames held by these live references, including assets evicted from the LRU cache. Cache hits consume the same allowances. Metadata limits are reduced to the remaining scan allowance before decompression and parsing, covering metadata-heavy zero-frame assets as well as pixel-heavy images. Exceeding a budget produces an explicit partial-result reason. These are per-invocation logical residency budgets, not exact allocator or process RSS bounds: input bytes, metadata object overhead, bounded inflation workspace, the intermediate PNG output buffer, profiles, and separate concurrent invocations consume additional memory. Default per-file, metadata, and decoder workspace ceilings are 64 MiB, 4 MiB, and 256 MiB respectively; decoded image dimensions are capped at 64 million pixels.
